# NNotion — frontend дипломного проекта

React, TypeScript, Vite. Два режима: обычное приложение с backend и автономная демонстрация для портфолио. Новые зависимости для демо не требуются.

## Локальный запуск демо

Требуется Node.js 22.12+ (проверено на Node.js 24). Выполняйте команды из `frontend-vite`:

```powershell
npm ci
npm run dev:demo
```

Если зависимости уже установлены, достаточно второй команды. Откройте адрес, напечатанный Vite (обычно http://localhost:5173).

Стартовый экран предлагает роли «Студент», «Преподаватель», «Администратор». Кнопка «Сменить роль» возвращает на выбор без перезагрузки. Роль сохраняется в `sessionStorage` текущей вкладки; токен, пароль, backend и база данных не нужны. Обычная сессия авторизации хранится отдельно.

В демо есть 23 пользователя, 3 группы, 24 занятия, 6 опросов с вариантами времени и голосами, личные задачи и уведомления. Даты отсчитываются от дня открытия приложения. Доступ к данным зависит от роли и группы.

Можно голосовать, создавать опросы и занятия, согласовывать результат закрытого опроса, управлять пользователями и группами, читать уведомления и отмечать задачи. Изменения API-данных живут в памяти до обновления страницы и сохраняются при переходах и смене роли. Личные задачи и настройки сохраняются в `localStorage` с префиксом `demo:`; тема приложения общая для обоих режимов. Импорт таблиц и смена пароля доступны только в полной версии; в демо эти действия отключены с пояснением.

## Сборка и проверка

```powershell
npm run check:demo
npm run build:demo
npm run preview
```

`check:demo` проверяет существующие API-модули с локальным адаптером: роли, области видимости данных, голосование, рекомендации, создание событий, уведомления и управление пользователями/группами. Backend не запускается.

`build:demo` создаёт статические файлы в `frontend-vite/dist`. `preview` показывает последнюю сборку (обычно http://localhost:4173); сам по себе он её не пересобирает. `build` и `build:demo` используют один каталог: перед публикацией нужна именно `build:demo`.

## Подготовка к GitHub Pages

Демо использует `HashRouter`: адреса имеют вид `https://<username>.github.io/<repository>/#/student`. Переходы, прямые ссылки и обновление вложенных страниц не требуют серверных перенаправлений. В demo-конфигурации Vite установлен `base: './'`, поэтому ресурсы загружаются относительно каталога сайта и имя репозитория не зашито в код.

Для будущей публикации соберите демо и используйте **содержимое `frontend-vite/dist`** как Pages artifact. На GitHub Actions рабочий каталог для `npm ci` и `npm run build:demo` должен быть `frontend-vite`, а путь загружаемого artifact — `frontend-vite/dist`. Публиковать backend и `.env` не требуется. Автоматический deploy workflow намеренно не добавлен: публикация выполняется отдельным согласованным действием.

Официальные справочники: [Vite — статическая публикация](https://vite.dev/guide/static-deploy.html), [React Router — HashRouter](https://reactrouter.com/api/declarative-routers/HashRouter).

## Как устроено демо

- `src/shared/demo/config.ts` — проверка режима `demo` и текст подписи.
- `src/shared/demo/data.ts` — связанные пользователи, группы, занятия, опросы, голоса, задачи и уведомления.
- `src/shared/demo/adapter.ts` — локальный Axios-адаптер с текущими форматами API, проверкой ролей и изменениями данных в памяти. Неподдерживаемый маршрут возвращает локальную ошибку, никогда не переключается на HTTP.
- `src/shared/api/base.ts` — единственная точка подключения адаптера. Страницы продолжают вызывать прежние `pollsApi`, `eventsApi`, `usersApi`, `groupsApi`, `notificationsApi`.
- `src/pages/demo-page/ui/DemoPage.tsx` — выбор роли. Существующие страницы входа и регистрации сохранены для обычного режима.

Для обычного режима используйте `npm run dev` или `npm run build`. Он сохраняет `BrowserRouter`, реальную авторизацию и API из `VITE_API_URL` (по умолчанию `http://localhost:3000/api`); переменные описаны в `.env.example`. Backend-код не изменён.
